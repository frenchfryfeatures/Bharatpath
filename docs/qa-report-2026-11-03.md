## Bugs found and fixed

### 1. Job lists showed annual salaries twelve times too high (web + mobile + API)

**Seen:** the candidate Jobs list and Home showed *Site Reliability Engineer
₹336–528 LPA*, *Senior Backend Engineer ₹288–456 LPA*; the job's own page said
₹28–44 LPA and ₹24–38 LPA. 13 of the 14 live jobs are annual.

**Cause:** `BoardJobSummary` carried no salary period, so every list assumed
monthly and multiplied by 12. Only the single-job response has `details`. The
mobile app drew every list salary as `₹600k–900k/mo`. The board's salary
filter compared raw paise, so an annual posting cleared every monthly floor.

**Fix:**
- API: `salary_period` on every board summary (list, detail, recommendations).
- API: `min_salary_minor` is a *monthly* floor (what both apps send) compared
  with each posting's top figure converted to a month
  (`jobs.repository._monthly_salary_max`).
- Assistant: "6 LPA" arrives as a year's rupees; it is divided down to a month
  (`assistant.domain.monthly_salary_floor_minor`).
- Web: `formatSalary` uses `salaryPeriod`.
- Mobile: `formatSalaryRangePaise(min, max, period)` draws an annual range in
  LPA, and `salaryPeriodSuffix` replaces the hard-coded `/mo` on the feed and
  home cards.
- Tests: `test_the_board_says_what_a_salary_is_per_and_filters_by_the_month`,
  `test_a_salary_floor_reaches_the_board_as_a_month`.

### 2. An employer who left sign-up after verifying email was locked out of it (web)

**Seen:** signing in as that account landed on **`/signup/student`**, signed
out. Reloading `/signup/employer` showed "Create your employer account" again,
a sign-up Cognito refuses for an existing email. There was no route back to the
organisation step.

**Cause:** `authService.me()` (run on every reload) always resolved the session
as the **candidate** pool, so a business account's 403 `no_active_membership`
became a "student", and the student gate sent it to candidate sign-up. The
employer sign-up resumed only an account that already owned an organisation.

**Fix:** `me()` reads the pool from the token's `iss` (`poolOfToken`, now
shared with `password.ts`). Sign-in sends a business account with no
organisation to `/signup/employer` or `/signup/college` by the tab it signed in
on. The employer sign-up resumes at the organisation step. `PortalAccessGuard`
sends `/employer/*` and `/college/*` to their own sign-up for such an account.
Verified against the live API for both employer and college.

### 3. Candidate sign-up reported one problem per press (web)

**Seen:** with a bad name, email, phone and city, pressing *Verify and
continue* said only "Choose experienced or fresher." Fix that, press again, and
only then hear about the phone, and so on. The phone error had no place under
its field.

**Fix:** `account-steps.tsx` validates every field in one pass, shows each
error under its field (phone and work status now included) and a summary line
when there is more than one.

### 4. A resume the server could not read said only "Some of the details provided are not valid." (web)

**Fix:** copy for the upload codes (`upload_unrecognised_type`,
`upload_unsupported_type`, `upload_legacy_doc_unsupported`, `upload_empty`,
`upload_too_large`, `resume_document_encrypted`, `resume_unreadable_document`,
`resume_too_long`, …) in `lib/api/error-message.ts`. A text file named `.pdf`
now reads "We can only read PDF and .docx files. This file is neither."

### 5. A street address or PIN code in "Current city" failed three steps later (web)

**Seen:** in onboarding step 1, `12 MG Road 411001` was accepted; the server
refuses it (the city is on every employer's masked card), so it surfaced only
as a failed save at the end. The profile editor showed the server's raw text
("Details: a city name is letters, spaces and . ' - only").

**Fix:** `career-form.tsx` checks the city with the backend's own rule on the
step it is typed in, with a plain message under the field.

### 6. An invitation to a closed job offered "View job details" to a "Job unavailable" page (API)

**Seen:** on Invites, the declined *Frontend* invitation linked to a job page
that answered 404.

**Cause:** the schema promises `job_title` is null once the job leaves the
board, but the title came from a read the board policy allows for any job the
candidate applied to, whatever its status.

**Fix:** `CandidateJobRef.on_board`; an invitation names the job only while it
is PUBLISHED. Test: `test_an_answered_invitation_names_no_job_once_it_has_closed`
(fails without the fix).

### 7. College analytics drew a withheld figure as 0 (web)

**Seen:** the college dashboard showed *Median score 0* beside "The cohort is
below the privacy floor". A withheld figure is `null`, never `0` (CLAUDE.md,
Day 18).

**Fix:** "—" for a `null` median, funnel row or monthly hires cell on the
dashboard and the analytics page.

### 8. "Copy code" on a college referral code threw when the browser refused the clipboard (web)

**Fix:** both copy buttons catch the refusal and show the code in an error toast
to copy by hand, like the dashboard's copy button already did.

### 9. A local frontend could not sign any candidate in (web, config)

The fallback Cognito candidate pool and client in `lib/auth/cognito.ts` were
the AWS account that expired on 2026-10-01, so without the `NEXT_PUBLIC_*`
variables every candidate sign-in failed with `ResourceNotFoundException`
(businesses worked). They now name the live pool, as `mobile-app/eas.json`
already did.

## Found, not changed (decisions or out of scope)

- **Signing up as an employer with a candidate's email** is accepted by
  Cognito and the code is emailed; the clash (`account_contact_in_use`)
  surfaces only after confirming. Checking earlier would need an endpoint that
  says whether an email has an account, which is an enumeration leak, so it is
  left as designed.
- **Employer pages fire `GET /employer/dashboard` on every page** even with a
  lapsed plan (402 each time, handled). Harmless, but noise in the console.
- **"Total work experience" is labelled Optional** but an experienced candidate
  must give at least one month. The label understates it.
- **KYB "Website" is free text** ("A social media page is fine"), so
  `not a website` is accepted. It is never copied to the public profile, whose
  own field requires `https://`.
- Pre-existing lint errors in `features/college/settings/hooks/use-settings.ts`
  (setState in an effect) were left alone.
