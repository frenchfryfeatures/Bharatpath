# 02 — The full API checklist

**Purpose of this doc: nothing gets missed.** Every HTTP endpoint the
backend serves is listed below, grouped by which surface calls it (shared,
candidate app, employer console, college console, admin console), with a
link to the guide document that walks through it.

**The tables are generated, not typed.** `backend/scripts/check_api_guide.py`
reads the app's own route table and rewrites everything between the markers
below. The same script reports any route that no guide document describes:

```bash
cd backend && source .test-env.sh
python scripts/check_api_guide.py           # report gaps; exit 1 if any
python scripts/check_api_guide.py --write   # regenerate the tables below
```

Run it after adding or removing a route. (This list used to be kept by hand.
By 2026-10-13 it was 33 operations short and its three running totals
disagreed with each other and with the app.)

**How to read a row.** Paths are relative to `/api/v1`. **Guide** links to
the document that describes the route; **missing** means none does yet,
which the script reports as a failure. Who may call a route, and what it
answers, is in that document.

**Two kinds of route a client must not depend on:**

- **Dev-only:** `POST /auth/dev/token` and
  `POST /billing/dev/payments/{payment_id}/simulate` exist only in local and
  dev builds. Staging and production never register them.
- **Flag-gated:** `POST /auth/otp/start` exists only with
  `AUTH_PHONE_OTP_ENABLED=true`. It is off by default, because phone OTP is
  deferred and nothing is sent by SMS (client, 2026-09-18).

**One module has no HTTP surface at all:** `integrity`. It runs as a
background task after scoring, and staff reach its results through the admin
console (`/admin/integrity/*`, listed below).
